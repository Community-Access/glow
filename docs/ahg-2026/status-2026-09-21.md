## 2a. What is now automated

Two checks landed in `d567058` (PR #113) and both have run green from `main`.

| Workflow | What it does | When |
|---|---|---|
| **Workshop Load Rehearsal** | 30 simulated participants through all eleven activities, in-process | PRs touching workshop code, weekly, on demand |
| **Production Validation** | Health, deploy state, workshop flags, MCP backend, every front-facing surface, and whether the worksheet pack is a real `.docx` | After every **successful** deploy, daily, on demand |

First run from CI, 30 participants: 1080 requests, 13.6s wall, median 262ms,
p95 1032ms, **no rate limits and no error responses**.

The rehearsal gates on **contention only** -- lock errors, 429s, error
statuses -- and never on latency. In-process, thirty threads share one GIL,
and on a shared runner the timings measure the runner. A latency gate would be
flaky, and a flaky gate is one people learn to ignore. `--gate all` remains
the default for a person running it deliberately before a conference.

### What the first CI validation run found

It came back **all required checks passed**, with three warnings that are the
point of the exercise:

```
OK    Health endpoint    ok, 148ms
WARN  Last deploy        not in this response; re-run
WARN  Workshop flags     /health returned a reduced payload with no feature_flags; re-run
```

That is the intermittent `/health` behaviour, caught in the wild on the first
automated run. Had the earlier version of the script still been in place it
would have reported **"all four workshop flags off"** -- a false alarm saying
the workshop is disabled, emailed to whoever watches CI.

**Characterising it, since it will need fixing server-side.** From this
machine, six consecutive requests all returned the complete payload in
2.32-2.42 seconds. From a GitHub runner, the same endpoint answered in 148ms
with `feature_flags` and `deployment` missing entirely. So the response
depends on the caller or the edge serving it, not on timing alone -- a cache
or a short-circuit path is the obvious suspect. Any monitor keying on those
fields will flap depending on where it runs from.

## 4. Decisions, locked

Thirteen, recorded in `plan.md` section 2. The load-bearing ones:

- **No house AI.** The workshop provides no free AI. Anyone who wants an
  assistant uses free ChatGPT, entirely at their option.
- **GLOW is the integral tool**, and it works with no account and no AI — its
  audit, fix and convert are deterministic, verified in the source.
- **Electronic handouts only.** We do not print. Every participant needs a
  device; a phone counts. This is the one place the simplification cost
  something, and it was taken deliberately.
- **No plumbing in the room.** No MCP, no CLI, no IDE, no vendor requirement.
  Tests enforce this against the generated packages and the prompt cards.
- **Text only into an assistant, never an upload.** Free accounts cap uploads
  at roughly two a day and do not cap text.
- **Follow-through is self-directed, support guaranteed on request** at
  `support@community-access.org`.

## 7. What I got wrong today, for the record

Because a reader should know which numbers in these documents were corrected
and why.

- **Miscounted the agents audit twice.** First by grepping `^name:` across
  whole files and catching example YAML in agent bodies; then by treating
  "does not start with `---`" as "has no frontmatter", when 70 files simply
  had a UTF-8 BOM in front of it. The second error hid the most important
  finding in that audit. Final numbers came from a committed script anyone can
  re-run.
- **Corrupted three files with shell escaping.** A `\a` became a BEL character
  in a README; two `\b` word boundaries became literal backspace bytes, which
  silently turned a plumbing guard into substring matching. All repaired, the
  test tree swept for control characters, and I stopped using heredocs for
  content containing backslashes.
- **Shipped a validator that cried wolf.** Its first run reported all four
  workshop flags off. They were on; `/health` had returned a reduced payload
  and `.get()` on a missing key is falsy. A false "the workshop is disabled"
  on conference morning is the worst thing that script could do, so it now
  distinguishes absent from off.
- **Said the agents work "does not block" the workshop, and framed that as
  "should not be done first".** Those are different claims. The agents
  repository is part of this session's credibility surface, and four of its
  fixes belonged on the pre-conference list.

Each of these was caught by checking rather than by being careful, which is an
argument for the scripts in `scripts/` over any amount of re-reading.
