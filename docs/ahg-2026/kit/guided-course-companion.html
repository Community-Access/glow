Step 1: understand the problem and the destination

Goal: See how an agent can help with one part of accessibility work while people remain responsible for the outcome.

An agent is a set of instructions followed by an AI assistant. It needs a task, appropriate evidence and a person who checks its work. A team adds specialist roles and a coordinator that routes work among them.

Consider these questions as the presenter talks. You may write answers or just think about them:

  • Where is the backlog? Think of a recurring task, such as explaining checker results or planning a document conversion. You do not need to describe a specific student.
  • What would a useful result look like? For Maria, a useful result is a short plan for a scanned reading with evidence, steps and a reviewer.
  • What still needs a person? A specialist checks the evidence, whether the proposed steps fit the situation and what remains untested. An AI answer alone does not establish compliance.

Keep: One non-sensitive task you might improve. If you have not chosen one, use Maria's alternate-format example or ask a helper.

Step 2: design your agent

Goal: Describe one job in six answers and save version 1. Choose a role card or adapt a ready-made agent.

Run /design-my-agent in Copilot Chat, or paste the block 2 text from the assistant page. Answer the assistant one question at a time. It may use slightly different wording or order. The following prompts work on paper too.

1. Role

Ask yourself: Who is this helper, and who will use its work? Name a role, not a real person's private details.

Start with: "You are a [kind of specialist] working for [who uses the draft]."

Example: "You are an alternate format planner working for a disability resource specialist."

2. Task

Ask yourself: What single job should it do? What input does it need? Choose a task small enough to test on one sample.

Start with: "Given [input], produce [result] for [purpose]."

Example: "Given an approved checker report and a generic format requirement, draft a plan for producing those formats."

3. Trusted guidance

Ask yourself: Which public standards and approved procedures should guide this job? What evidence should it cite? If you do not know a specific criterion, write that it needs verification.

Start with: "Use and cite [trusted sources]. If evidence is missing, ask for it rather than guess."

Example: "Use WCAG 2.2 and the ACB Large Print Guidelines. Verify that a cited criterion applies." Do not paste a private procedure into an unapproved tool.

4. Output format

Ask yourself: Who will read the answer and what shape makes it useful? Consider a short plan, a list of findings or a draft reply.

Start with: "Return [sections or columns], including [evidence and review information]."

Example: "Give the problem in one line, numbered steps with responsible roles, the formats to deliver and a review checklist."

5. Example

Ask yourself: What would one useful answer look like? A short fictional example shows the assistant the shape you want. It is not proof about an actual document.

Start with: "For [fictional input], a good answer would ..."

Example: "For a scanned reading, obtain clean text, check it against the original, then plan large print and audio."

6. Human review

Ask yourself: What role checks the result, what do they compare it with and who decides before it is used? Naming a role is enough.

Start with: "Before use, [reviewer role] checks [specific things] against [source]."

Example: "The alternate format specialist checks the converted text against the original. The student confirms that the format works for them."

Step 3: try it and improve it

Goal: Test what happens before a checker report is supplied, then save version 2.

  1. Run /try-my-agent, or paste the block 3 text in the same assistant conversation. Choose one fictional PSY 101 file that fits your task.
  2. Read the answer. Ask: "What does the answer actually know? What is it assuming? Did it ask for missing evidence?" A request for missing evidence is a successful result.
  3. Save the chosen filename and the complete actual first answer in your workshop notes. You will need both for the next step.
  4. Run /review-my-agent, or paste the block 3 review text. Read the suggested change and why it was suggested. Accept it or say what you want instead.
  5. Save and reopen version 2. Keep version 1 as well. See step card 3 for your path's exact instructions.

Example: If the agent calls an unseen document compliant, revise the instructions to say: "Work only from supplied evidence. Ask for the missing report. Do not claim compliance."

Keep: The filename, first answer and version 2. If you cannot run an assistant, use Maria's clearly labelled written example and say that it is an example.

Step 4: add evidence and check the answer

Goal: Use the same sample file with its checker report, compare the answers and save version 3.

  1. Find your first answer and filename. Run /ground-my-agent, or paste block 4 text. Select that same file. The supplied reports include GLOW document audits and an axe report for the web page.
  2. Read the new answer. Ask: "Which claim came from the report? Which source and WCAG criterion does it cite? What remains untested?" Open at least one source and check whether it supports the claim.
  3. Compare it with the first answer. Record what changed and what a person must still check. If the first answer is missing, mark the comparison incomplete rather than inventing it.
  4. Run /review-my-agent, or the block 4 review text. Adjust the agent if needed, save version 3 and reopen it. Step card 4 gives path-specific saving instructions.

Example: A report says a PDF consists of pictures of text. The agent can suggest obtaining clean text. A specialist still verifies the source, the suggested criterion and the converted text.

Keep: Both actual answers, the evidence reference and version 3. A citation or checker result is not proof of full accessibility.

Step 5: join the office team

Goal: See how your agent's specialist instructions contribute to one report, then save version 4.

  1. Run /run-the-office, or paste block 5 text. The coordinator works through the fictional course using specialist roles, including yours. If the answer stops partway, ask it to continue.
  2. Find your agent's contribution. Ask: "What file was routed to it? What evidence supports its contribution? What does a person still need to review?" Look for these in the team report.
  3. Save the complete report in your workshop notes. If a finding has no supporting evidence, mark it for further review.
  4. Run /review-my-agent, or the block 5 review text. Consider the suggested change, save version 4 and reopen it. Keep your earlier versions. Step card 5 has the full steps.

Example: The coordinator routes the scanned reading to Maria's planner. Its section proposes a clean source and formats, and names a specialist as reviewer.

Remember: The workshop team uses specialist instructions in sequence in one assistant conversation. It is not an independent second review or proof of a new scan of every file.

Keep: Your report, evidence and version 4. The presenter's full-project demonstration uses the same fictional course; you may watch or use its written example.

Step 6: review and decide whether to share

Goal: Have either a confirmed public contribution or a reviewed local copy with a specific next step.

  1. Read version 4. Remove private details, internal procedures and non-public links. Ask: "Do I have permission to publish these instructions under the MIT license?" If unsure, mark approval pending and keep the copy locally.
  2. If publication is approved, open the share page, choose your reviewed agent file or paste its text, and follow the form. Opening the GitHub form sends your text to GitHub before you submit.
  3. Check the privacy box, submit the issue and wait for the collection reply. A submitted issue is not confirmation; the reply tells you when it is in the collection.
  4. If permission or GitHub is unavailable, save the reviewed copy. Write who will decide, what approval is needed and when you will follow up. Step card 6 has the full steps.

Example: "Approval pending: ask the director whether these generic instructions can be published under MIT by next Friday." Do not collect someone else's work without their permission.

Keep: The confirmed collection link or your local reviewed file and follow-up. Both are valid outcomes.

Watch the capstone: a coworker using shared tools

The presenter shows reviewed instructions in ChatGPT with a prepared GLOW connection. You do not need an account or connection for this demonstration.

  1. Instructions: What is the fictional faculty coach asked to do? It drafts advice from supplied evidence and requires human review.
  2. Evidence: Which tools actually ran? The presenter opens the results for heading structure, link text and the supplied text/background colors. If a tool fails, that check is "not checked." A recorded or written fallback is labelled as such.
  3. Limits: What did those tools not test? They did not operate the page or establish its screen reader experience. The presenter separately tries keyboard navigation without submitting the form.
  4. Review: Does the draft distinguish tool results, source observations and manual checks? Does a person verify the claims before anything is sent?
  5. Team use: Who owns the instructions, who approves the tool connection and permitted data, and who tests access with another authorized user? Workspace sharing remains pending until approved and tested.

Keep: This distinction: instructions describe the work, tools provide particular results, and people verify and decide. The capstone guide contains the detailed demonstration and fallback.

Step 7: make your 30-day plan

Goal: Make a small, safe plan for one workflow. Use /my-30-day-plan, the block 7 browser text, or paper. Maria's worked example includes a complete plan.

Answer each question. You can use these sentence starters:

  1. Workflow: "I will explore help with [one existing task]." Example: draft production plans for scanned readings.
  2. Handoff: "When [trigger] happens, staff provide [approved evidence]; the draft goes to [place]." Example: a request starts the review; an approved report goes in; the draft returns to a staff ticket.
  3. Partner: "I will work with [role]." Example: a specialist or faculty colleague who can review the result.
  4. Safeguard: "Before the draft is used, [reviewer role] checks [what] against [source]." Example: the specialist checks the plan against the reading.
  5. Tools and data: "The approved assistant is [tool], and permitted inputs are [data]." If unknown, write "pending" and who will confirm it. Do not assume approval.
  6. First step: "This week I will [small action]." Example: rehearse on a fictional reading or request a policy review.
  7. Approval: "I need [role] to know or approve [change]; I will ask by [date]." A workflow map and an approval request count when no AI is approved yet.
  8. Day-30 check: "I will compare [baseline and measures] and [role] will decide whether to continue, revise or stop." Include total staff and review time, errors, rework and on-time delivery.

Review the plan with a partner

Explain the trigger, input, draft destination, reviewer, deadline, approval and stop rule. Ask your partner to identify one unclear handoff and check the baseline and day-30 measure. If working alone, compare your plan with Maria's. Correct the draft and save the final plan.

Set a stop rule

Try up to five fictional or approved non-sensitive examples alongside the existing process. Stop for private data, unverifiable evidence, a missing required review or a threatened deadline. Use the existing process and notify the responsible team. Never delay an accommodation for a pilot.

Keep: The final plan, the person responsible for any pending approval and your review date. During the session you may add a one-sentence commitment without names at letitglow.app/w/ahg-2026/11.

After the workshop

Start with your saved agent and plan. Confirm your institution's rules before using any AI tool or data. Rehearse on a fictional or approved non-sensitive example, record the agent version and evidence, and have the named reviewer check the result. Compare the full process with the baseline before expanding it.
